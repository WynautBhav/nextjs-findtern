## Verdict: GO, if every pre-flight box below is ticked

**Cutover model:** full replacement, not side by side. findtern.in moves to
the new app. The legacy PM2 process `findtern-app` is **stopped**, not just
unrouted, because its schedulers start on boot with no switch. It stays
installed as the rollback target. Both apps never run against the database
at the same time.

### Pre-flight: must be done before the switch (NO-GO if any is missing)
- [ ] **P1** Deploy `scripts/legacy/argon2-compat.patch` to the legacy app and
      restart it. Without this, a rollback locks out everyone who signs up
      or changes their password in the new app (DB-01). The patch applies
      cleanly and covers all 6 legacy password checks. Tested: legacy accepts
      the new app's argon2 hashes and still accepts plain text.
- [ ] **P2** Production `.env` is complete (list in step 3 below). In
      particular `MAIL_MODE=send` and `SCHEDULERS=on` (the defaults send no
      reminders), and `PAYMENTS_MODE` unset.
- [ ] **P3** Live Razorpay keys and webhook secret are set. Legacy has no
      webhook, so nothing to unhook there.
- [ ] **P4** `launch-blockers` is merged and built in `/srv/findtern-next`.
- [ ] **P5** A backup has been taken *and restore-tested* within the hour
      before the switch.
- [ ] **P6** Someone with Razorpay dashboard access is on hand for the
      in-flight payment check (step 10).

### Accepted risks (go live with these, eyes open)
- **Rollback is not free.** These new-app writes look wrong in legacy:
  - files uploaded in the new app (DB-12);
  - the hiring fee inside `totalPrice` on new offers: legacy would bill the
    leftover ₹5,000 as an extra month, but only at the *end* of a monthly
    placement (DB-30);
  - legacy admin money totals and billing (DB-04, DB-05, DB-07);
  - the hybrid split, closed projects, and "Present" job dates (EMH-02,
    EMH-03, INT-02).

  None crashes legacy or loses data. Treat rollback as an hours-long
  measure, not days.
- **Invoice numbers change format** to FT/2026-27/NNNN. Earlier customer
  invoices were DDMMYY-NN (EMH-09). Tell accounts before launch.
- **Ops staff can't score or approve interns** until a super admin grants
  `interns:write` to "Executive - Operations" in /admin/roles (ADP-17,
  reproduced in testing). Decide on launch day. Only the super admin can
  score until then.
- **464 plaintext passwords stay plaintext** until each user logs in, with
  `PASSWORD_UPGRADE=on`. Bulk re-hash once the rollback window closes.
- **24 interns** with a legacy "Present" end date get an actionable error on
  re-submit (INT-02). One click fixes it.

### NO-GO / roll back if, during the first hour
Login fails for existing users, checkout or verify returns 5xx, the
migration does anything other than the rehearsed output, or `pm2 logs`
shows repeated errors on /api/auth/* or /api/*/payment/*.

## Runbook

All on the KVM as root. Node 22.21 via nvm (PM2 runs from
`/root/.nvm/versions/node/v22.21.1/bin`). Legacy: PM2 app `findtern-app`,
`/var/www/findtern-v1`, port 5000. The new app: PM2 app `findtern-next`,
`/srv/findtern-next`, port 3001. Postgres 16 on the same box, DB `findtern`.

### T-1 (the evening before)
1. **App checkout and build** (do not start or migrate yet):
   ```bash
   git clone https://github.com/WynautBhav/nextjs-findtern.git /srv/findtern-next
   cd /srv/findtern-next && git checkout launch-blockers   # or the branch it is merged into
   mkdir -p /srv/findtern-uploads
   npm ci && npm run build
   ```
2. **Legacy compat patch (P1).** Reversible: keep the old build.
   ```bash
   cd /var/www/findtern-v1
   cp -a dist /root/legacy-dist-pre-argon2
   git apply --check /srv/findtern-next/scripts/legacy/argon2-compat.patch && git apply /srv/findtern-next/scripts/legacy/argon2-compat.patch
   npm install @node-rs/argon2@2.2.1        # the patch adds it to package.json only
   npm run build && pm2 restart findtern-app
   ```
   Smoke test: log in on findtern.in with an existing (plain-text) account.
   Undo: `rm -rf dist && cp -a /root/legacy-dist-pre-argon2 dist && git checkout -- . && pm2 restart findtern-app`.
3. **`/srv/findtern-next/.env`** (from `.env.example`):
   - `NODE_ENV=production`, `PORT=3001`, `PUBLIC_ORIGIN=https://findtern.in`, `TRUST_PROXY=1`
   - `DATABASE_URL=postgresql://<app user>:<pw>@127.0.0.1:5432/findtern` (same credentials legacy uses)
   - `SESSION_SECRET`, `SIGNING_SECRET`: fresh, 32+ random characters each
   - `MAIL_MODE=send`, `SMTP_*` (production sender), `SCHEDULERS=on`
   - `PASSWORD_UPGRADE=on` (only once step 2 is done), no `PAYMENTS_MODE`
   - `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` (live)
   - `GOOGLE_CLIENT_ID/SECRET`, `GOOGLE_OAUTH_REDIRECT_URI=https://findtern.in/auth/google/callback`,
     `FINDTERN_GOOGLE_OAUTH_REDIRECT_URI=https://findtern.in/google/callback` (the legacy URIs; both are rewritten)
   - `UPLOAD_ROOT=/srv/findtern-uploads`, `LEGACY_UPLOAD_ROOT=/var/www/findtern-v1/uploads`
   - `FINDTERN_LEGAL_NAME`, `FINDTERN_GSTIN`, `FINDTERN_BILLING_ADDRESS`, `FINDTERN_BILLING_EMAIL`
     (the defaults already match legacy; set them anyway)
   - `INCRUITER_WEBHOOK_SECRET` if Incruiter posts results; `DEEPSEEK_API_KEY` for the chatbot
4. **nginx file for the new app.** Copy `deploy/nginx-findtern.conf` to
   `/etc/nginx/sites-available/findtern.in.next` and uncomment the two
   certbot `ssl_certificate` lines (the paths match the live certificate).
   Then make a copy of the live file, **unchanged**:
   `cp /etc/nginx/sites-available/findtern.in /etc/nginx/sites-available/findtern.in.legacy`

### T0 (the switch, at low traffic; about 15 minutes)
5. **Backup and restore test (P5):**
   ```bash
   mkdir -p /var/lib/postgresql/findtern-backups && chown postgres /var/lib/postgresql/findtern-backups
   sudo -u postgres env DB=findtern OUT=/var/lib/postgresql/findtern-backups UPLOADS=/var/www/findtern-v1/uploads bash /srv/findtern-next/deploy/backup.sh
   ```
   (Run as `postgres`: root gets peer-auth refused.) Note the dump path.
6. **Stop legacy:** `pm2 stop findtern-app` and note the time (**T0**). This
   also stops its schedulers.
7. **Migrate:**
   ```bash
   cd /srv/findtern-next && node --env-file=.env --experimental-strip-types scripts/migrate.ts
   ```
   Expected, exactly as rehearsed on today's dump: one `skipped:
   users_country_phone_unique` (102 legacy Google placeholder phones, which
   is fine), `baselined existing schema at 0000`, then 0001–0006 `ok`, then
   `legacy backfill … ok`. Anything else → roll back (step R).
8. **Start the new app:**
   `pm2 startOrReload deploy/ecosystem.config.cjs --env production && pm2 save && curl -sI http://127.0.0.1:3001 | head -1`
9. **Switch nginx:**
   ```bash
   ln -sf /etc/nginx/sites-available/findtern.in.next /etc/nginx/sites-enabled/findtern.in
   rm -f /etc/nginx/sites-enabled/api.findtern.in   # plain-HTTP mirror of legacy; it would 502 now
   nginx -t && systemctl reload nginx
   ```
10. **Payments in flight.** In the Razorpay dashboard:
    - set the webhook to `https://findtern.in/api/webhooks/razorpay` (events
      `payment.captured`, `order.paid`) with the secret from `.env`;
    - list payments captured between T0 − 30 min and T0 + 30 min and match
      each `order_id` against `intern_payments` / `employer_payments`;
    - settle any that are missing by hand (legacy checkouts open at the
      switch can't finish on the new app).
11. **Google Meet:** /admin → connect Google Calendar, then book one test
    interview and confirm it gets a Meet link. Campus-drive calls use the
    same calendar and have no fallback link in production, so this must be
    done before the first college drive.
12. **Smoke test, 15 minutes, on findtern.in:**
    - log in as an existing intern, an employer and an admin (plain-text
      passwords);
    - sign up a new intern with the email code;
    - a `/uploads/...` identity document opened while logged out returns 401;
    - the employer candidate list loads;
    - a ₹1 test promo order in Razorpay live, if accounts allow it;
    - `pm2 logs findtern-next --lines 200` is clean.
13. **Keep Postgres local-only.** The app connects over 127.0.0.1. Check that
    the firewall and `pg_hba.conf` accept database connections from localhost
    only, reload Postgres, and rotate the DB password. Use SSH for any remote
    access.
14. **Admin roles:** if approved, grant `interns:write` to "Executive -
    Operations" in /admin/roles (ADP-17).

### R. Rollback (under 5 minutes; no database restore needed)
```bash
pm2 stop findtern-next
pm2 start findtern-app
ln -sf /etc/nginx/sites-available/findtern.in.legacy /etc/nginx/sites-enabled/findtern.in
ln -sf /etc/nginx/sites-available/api.findtern.in /etc/nginx/sites-enabled/api.findtern.in
nginx -t && systemctl reload nginx
```
- **Why no DB restore:** the migrations only add columns and tables, every
  new NOT NULL column has a default, and legacy runs on the migrated schema.
- **Never run `npm run db:push` from legacy:** it would drop
  `invoice_number`, `applies_to` and `invoice_counters`.
- **Point the Razorpay webhook away** from the new app. Legacy has none.
- **Known rollback gaps:** see "Accepted risks".
- **Restore the backup only** if the migration itself failed half-way:
  `pg_restore --clean -d findtern <dump>`, with both apps stopped.
